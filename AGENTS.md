# AGENTS.md

## Project Overview

A repository for storing FHIR documentation and generating derived documents from it. It holds FHIR documentation in several versions and from several publishers: the official HL7 specification and vendor documentation (Epic, Meditech, Oracle Health and others). Each source has its own folder with the original input in its primary format (ZIP or other) and PDFs regenerated from it. The PDFs are uploaded to NotebookLM as sources so the corpus works as a queryable wiki.

## Layout

- `official-docs/`: official HL7 FHIR documentation, one folder per FHIR version.
- `vendor-docs/`: FHIR implementation documentation published by EHR vendors, one folder per vendor and version (e.g. Epic, Meditech, Oracle Health).
- `.agents/skills/`: agent-agnostic project skills (source of truth). `.claude/skills/<name>` is a symlink to it, because Claude Code reads only `.claude/skills/`.

## Naming Conventions

- Language: file and folder names, and all documentation, are in English.
- Folder names: lowercase, kebab-case, `<source>-<version>`.
- PDF names: `<Prefix>_<NN>_<chapter>_<Title>[_partK-of-N].pdf`. `NN` is a zero-padded sequence in the order of the source's table of contents. Chapters too large for one source are split into `partK-of-N`.
- Order follows the source's own TOC, not alphabetical order.
- No spaces or non-ASCII characters in file names.

## Generating PDFs

For every new documentation source (another FHIR version, Epic, Meditech, Oracle, etc.), generate the PDFs with the project skill `docs-to-notebooklm-pdf` (`.agents/skills/docs-to-notebooklm-pdf/`). Do not write ad-hoc conversion scripts.

- Input: a ZIP or folder of HTML/Markdown/text, already downloaded or mirrored. The skill does not fetch anything.
- Output goes into the source's own folder next to the original input, together with `REPORT.md` (English, Markdown; this exact name).
- A table of contents is optional. If one exists (e.g. `toc.html`), it defines the order and chapters; if not, the skill falls back to path order grouped by top-level folder.
- PDFs use the built-in Helvetica/Courier fonts; documentation is assumed to be English.

## Git Workflow

- Commit directly to `main`. Do not create feature branches or open pull requests: the repo holds data and docs, so there is nothing to code-review.
